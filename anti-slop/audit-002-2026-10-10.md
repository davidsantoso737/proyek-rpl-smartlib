# Audit 002 — Librarian dashboard targeted refinement (2026-10-10)

Scope: five requested refinements to the current librarian dashboard.
Static inspection of `templates/base.html`, `templates/accounts/dashboard.html`,
`templates/partials/_librarian_sidebar.html`, `apps/accounts/views.py`,
`apps/circulation/models.py`, `apps/circulation/services.py`,
`apps/circulation/views.py`. No new screenshots supplied beyond
`docs/design/references/bookhive.jpg` (already inspected in audit 001).

Design Read: same operations dashboard for school librarians, calm academic
style, dial ENERGY 1 / RHYTHM 2 / MOTION 1. Targeted refinement, not redesign.

## Findings (approved for fix by the task directive)

1. [MEDIUM] Full-width brand header sits above sidebar and content; brand
    is not part of the sidebar. (R-05: layout not built around content;
    R-20: hierarchy unfocused.)
2. [HIGH] Hamburger (`xl:hidden`) replaces notification/profile below
    1280px, so desktop widths lose direct access to both controls. The
    breakpoint logic, not the controls, is at fault. (R-03: mobile pattern
    applied where the desktop pattern belongs; R-26: controls not directly
    operable on desktop.)
3. [MEDIUM] KPI row shows queues only; domain defines `LOAN_ACTIVE`
    ("ACTIVE", set at handover in `services.py`, pending excluded) but no
    card surfaces it. (C-3: real content need unmet; R-17: count from DB.)
4. [LOW] AI Assistant item in the librarian sidebar serves no librarian
    workflow; the feature belongs to students/teachers. (C-3: section
    exists without content need; R-20.)
5. [LOW] Four-card grid (`sm:2 xl:4`) needs rebalancing once a fifth card
    joins, or cards compress. (R-05: RHYTHM dial not held.)

## Data-source verdicts (verified, not assumed)

- Active loans: `Loan.status == "ACTIVE"` (`LOAN_ACTIVE` in
  `apps/circulation/services.py`, set in handover flow, cleared to
  `LOAN_COMPLETED` on return). `PENDING_APPROVAL` is explicitly not
  active. No existing context variable supplies it; smallest change is a
  read-only `.count()` in `pustakawan_dashboard_view`, mirroring the
  `librarian_pending` processor's local-import plus try/except style.
- No librarian-facing all-active-loans list exists (`loan_list_view` is
  own-history only), so the new card links nowhere rather than to a wrong
  destination (R-24).
- AI entry points: sidebar partial only (librarian). `base.html` desktop
  and mobile `ai:assistant` links plus dashboard `ai:recommendations`
  links serve students/teachers and stay.

## Follow-up (2026-10-10): findings 1-5 fixed

- F1/F2 (header): `base.html` librarian shell is now rail plus workspace
  column; the full-width brand bar is gone for librarians and the brand
  lives atop the sidebar via new `partials/_brand.html` (shared mark,
  semibold sidebar title, divider before first group). Workspace topbar
  holds one coherent control set: hamburger (`lg:hidden`), bell always,
  full profile from `sm:` up and avatar-only below. Student/teacher
  header, drawer, and containers are byte-identical (brand include
  renders the same classes).
- F3 (KPI): `pustakawan_dashboard_view` adds read-only `active_loans`
  (`Loan` count with `LOAN_ACTIVE`, local import plus try/except, no
  migrations or rule changes). Fifth card `Peminjaman aktif` reuses the
  card treatment and book-open glyph; it is a static card because no
  librarian-facing all-active-loans list exists (`loan_list_view` is
  own-history), so linking it anywhere would be a wrong destination
  (R-24). Grid is now `2 / lg:3 / min-1440px:5`.
- F4 (AI): item removed from `_librarian_sidebar.html` (both rail and
  drawer, same partial). Desktop/mobile `ai:assistant` and both
  `ai:recommendations` links for students/teachers verified intact.
- F5 (grid): container widened to `max-w-[1400px]` for librarians only,
  the demonstrably necessary change so five cards fit at wide widths.
