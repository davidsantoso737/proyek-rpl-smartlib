## Findings

1. [HIGH] Desktop librarian nav hides 10 destinations inside two dropdowns
    (Sirkulasi, Kelola) with no persistent grouped sidebar. (R-24: nav must
    reflect real structure; R-26: queue destinations not reachable at a glance.)
2. [HIGH] Pending-queue badges (`pending_loans`, `pending_ebooks`,
    `pending_materials/deletions`) render only inside closed dropdowns, so a
    librarian cannot scan what needs action. (R-27: data view lacks a
    perceivable operational state.)
3. [HIGH] Dashboard has no KPI row from real `pending_*` data and no
    operational table; the only queue signal is one paragraph plus a single
    approval link. (R-38: real content exists but is not shown; C-3.)
4. [MEDIUM] Active route is invisible at a glance when it sits inside a
    closed dropdown; no persistent active group context. (R-04: relevance
    signal missing where the decision happens.)
5. [MEDIUM] Dashboard `Administrasi` list duplicates header nav as plain
    text links with no icons, hierarchy, or status, competing with the real
    nav instead of supporting a task. (R-05: structure not built around the
    librarian decision; C-3.)
6. [MEDIUM] Nav items have no icons while the task requires consistent
    icon-to-label scanning; current inline-SVG set covers only chevron and
    hamburger. (R-04: icon relevance undecided, reason not written.)
7. [LOW] Dashboard cards use one flat treatment (`rounded-xl`,
    `border-slate-200`, `bg-white`, no shadow scale) for account info,
    attention banner, and admin links alike, so KPI, operational, and
    secondary panels cannot differentiate by spacing/scale. (R-11, R-12.)
8. [LOW] Page title block duplicates `_page_header.html` markup inline
    instead of reusing the partial. (R-31: reuse reason not followed.)
9. [LOW] Mobile nav already groups (Utama/Sirkulasi/Kelola/Akun) but desktop
    has no equivalent grouping, so the two states diverge in information
    architecture. (R-05: RHYTHM dial not held across breakpoints.)

Out of scope (not touched without separate approval): student/teacher
dashboards, all workflows, models, views, URLs, permissions, forms.
