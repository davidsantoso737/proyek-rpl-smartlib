# Audit 012 — Polish form tambah buku & e-book (2026-10-10)

Scope: `manage_book_form.html`, `manage_ebook_form.html`, new
`partials/_author_picker.html`, scoped CSS in `static/src/input.css`,
presentational `Meta.widgets` rows in `forms.py`. Inspected: both
templates (sections, back link, submit), `BookForm`/`EbookForm` (fields,
labels, `authors` M2M checkbox, `style_fields`), `#id_authors` CSS, the
global `:focus-visible` rule, sidebar/header/tokens.

Findings driving the plan:
- Thick select focus = stacked indicators: `INPUT_CLASS` paints
  `ring-2 blue-500` while global unlayered CSS forces a 2px `#1d4ed8`
  outline on top. Fix scoped to `.manage-form` (drop the outline where
  the ring already signals): blue-500 on white measures 3.68:1, which
  clears the 3:1 focus-indicator bar, so visibility is preserved with a
  single controlled signal. `INPUT_CLASS` itself untouched (global).
- Author wall = Django `CheckboxSelectMultiple` (`name="authors"`,
  values = author PKs, M2M preserved server-side). Fix is progressive
  enhancement only: searchable capped panel plus live count summary
  over the real checkboxes; filtering only hides rows, checked state
  (including invalid-rerender state) is never touched; no endpoint.
- `description` renders `rows=10`; set `rows=4` via per-form `Meta`
  presentation (same pattern as existing `bio` rows=3; validation
  untouched).
- Field icons skipped with reason (R-04): labels are explicit
  Indonesian; icons would duplicate meaning rather than aid
  recognition.
- Header integrates into the card (compact h1, kept subtitles, divider,
  secondary back control reusing existing destinations); authors/status
  keep their 2-col section with one concise status note each; Batal
  already exists from the prior phase.
