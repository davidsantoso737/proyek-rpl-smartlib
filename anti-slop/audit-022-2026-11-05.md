# Audit 022 - Konfigurasi AI multi-provider (2026-11-05)

Scope: `templates/core/policy.html` bagian AI Assistant, `apps/core/views.py`,
`apps/core/urls.py`, `apps/ai/forms.py`, `apps/ai/configuration.py`,
`apps/ai/models.py`, `apps/ai/providers.py`.
Inspeksi: alur GET/POST halaman konfigurasi, form endpoint/API key/model,
discovery model, uji koneksi, aktivasi, reset, dan fallback environment.
Tidak ada perubahan kode atau database pada tahap audit ini.

## Temuan

1. HIGH `policy.html` bagian AI Assistant belum punya pemilih provider
   tersimpan. Berpindah provider memaksa pengguna mengetik ulang URL endpoint
   dan API key. (C-2 Functional Completeness, R-27)
2. HIGH Status "aktif" hanya satu nilai global dan tidak melekat pada pilihan
   provider. Saat konfigurasi menjadi banyak, pengguna tidak bisa melihat
   provider mana yang aktif, mana yang tersimpan, dan mana yang belum
   diverifikasi. (R-27, R-09)
3. HIGH `configuration.py` mengunci satu baris `pk=1` pada `_saved_row`,
   `save_configuration`, dan `reset_configuration`. Struktur tabel dapat
   menampung banyak baris, tetapi logika aplikasi belum bisa memilih baris
   selain `pk=1`. (C-2, C-4)
4. MEDIUM Placeholder API key masih generik, "Kosongkan untuk memakai key
   tersimpan", tanpa menyebut provider terpilih. Pada multi-provider ini
   berisiko membuat pengguna mengira key provider lain yang dipakai.
   (R-31, batasan tugas nomor 10 dan 11)
5. MEDIUM Aksi hapus hanya tersedia sebagai reset konfigurasi tunggal. Belum
   ada alur hapus per provider dengan konfirmasi dan penjagaan provider aktif.
   (C-2, R-27)
6. LOW Pesan error field dirender sebagai paragraf biasa tanpa
   `aria-describedby` yang menghubungkan ke input terkait. (R-32)
7. LOW Radius elemen status memakai campuran `rounded-lg` dan `rounded-xl`
   untuk level visual yang setara. (R-11, konsistensi DESIGN.md bagian 9)

## Catatan yang sudah sesuai

- Kontras teks status utama memakai kombinasi emerald/blue/amber 50 dengan
  teks 800/900, aman untuk WCAG AA. (R-25)
- Tombol utama, tombol sekunder, input, dan select sudah memakai tinggi
  minimal 44px serta focus ring. (R-03, R-32)
- Panel discovery model sudah punya status kosong, memuat, dan gagal lewat
  `#ai-model-status`. (R-27)
- Badge status di kanan atas adalah status fungsional, bukan badge dekoratif.
  (R-09)
- Tidak ada em dash baru pada teks yang ditulis agen. (R-02)

## Tindakan yang diusulkan

1. Tambah kolom `name` pada `AIConfiguration` lewat satu migrasi aditif, isi
   nama provider lama dari host endpoint, dan pertahankan baris NVIDIA apa
   adanya.
2. Ubah service konfigurasi agar membaca baris aktif (`is_enabled=True`),
   mendukung daftar provider, dan memakai API key milik provider terpilih
   saja.
3. Ubah halaman konfigurasi menjadi pemilih provider berbentuk dropdown,
   detail provider terpilih, form tambah provider, aksi uji, simpan, aktifkan,
   dan hapus dengan konfirmasi.
4. Tambah pengujian multi-provider, isolasi API key, aktivasi tunggal, dan
   fallback environment.
